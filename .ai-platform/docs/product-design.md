## Product Positioning

TellPlot 是面向财务分析与汇报场景的可编辑叙事图表能力。产品帮助用户在不改写原始财务数据的前提下，通过直接操作、结构大纲和确定性命令调整图表的叙事顺序、层级、分组与表达重点，并生成适合演示文稿使用的结果。

产品品牌、代码仓库和包命名空间统一使用 `TellPlot` / `tellplot` / `@tellplot`。产品不以“通用 G2 交互中间件”为定位，也不以替代 BI、数据准备平台或 PowerPoint 为目标。

## Delivery Form

第一阶段交付一个可嵌入业务系统的 React 组件包，并提供一个只承担示例数据、场景验证和视觉验收的薄参考编辑器。参考编辑器不得形成独立于组件包的第二套领域状态或业务逻辑。

公共组件负责数据契约、编辑命令、财务不变量、图表渲染、结构大纲、历史、持久化和导出。宿主系统负责数据获取、权限、页面导航、AI provider 和服务端存储。

## Target Users

### TU-001 财务分析人员

负责经营分析、预算分析、实际与预算差异分析、管理层汇报和 PPT 图表制作，需要快速调整财务图表的叙事结构。

### TU-002 财务系统与 BI 开发人员

负责把可编辑财务图表嵌入企业内部分析系统，需要稳定的数据边界、事件契约和可扩展组件。

## Jobs To Be Done

### JTBD-001 调整财务叙事顺序

当用户需要解释利润、收入、成本或预算差异时，可以直接重排贡献项，使图表顺序符合汇报逻辑，而不是受原始数据顺序限制。

### JTBD-002 控制分析层级

当明细过多时，用户可以把项目组织成组并折叠；需要追溯时可以展开，同时保持合计准确和来源可见。

### JTBD-003 快速形成汇报材料

用户完成分析后，可以保留视图配置并导出清晰、稳定、适合演示文稿使用的图表。

### JTBD-004 用 AI 加速复杂调整

当排序、归组或表达规则需要多个步骤时，用户可以用自然语言描述目标，检查系统提出的修改后再执行。

## User Stories And Scenarios

### US-001 瀑布图拖拽排序

财务分析人员可以拖动贡献项改变展示顺序；拖动不会修改金额、来源或最终合计。

### US-002 分组、折叠与展开

财务分析人员可以多选同层连续项目或分组创建递归分组树、解散指定分组、折叠和展开，并查看任意层级分组的聚合值与来源明细。

### US-003 条形图与柱状图叙事排序

财务分析人员可以在分类条形图或柱状图中重排分类、固定关键分类并按组控制层级。

### US-004 精确结构编辑

用户可以在结构大纲中完成精确排序、层级调整和键盘操作；图表与大纲保持同步。

### US-005 可恢复编辑

用户可以撤销、重做、保存和恢复视图编辑，并理解每一步修改的对象与结果。

### US-006 AI 辅助编排

用户可以输入“把低于 100 万的费用合并为其他，并按不利影响排序”等指令，预览候选操作并选择应用或拒绝。

### US-007 演示文稿输出

用户可以导出保持当前顺序、分组、折叠、标签和强调样式的高质量图表，用于 PPT 汇报。

## Core User Journey

1. 用户导入或接收结构化财务数据。
2. 用户选择瀑布图、条形图或柱状图。
3. 系统生成可编辑的初始图表和结构大纲。
4. 用户通过图表拖拽或大纲调整顺序与层级。
5. 用户按需使用 AI 生成批量调整建议。
6. 系统校验总额、来源和锁定项等财务不变量。
7. 用户保存 `ViewSpec` 并导出汇报图表。

## Functional Requirements

### FR-001 不可变原始数据

系统必须把原始数据与图表视图配置分开保存。任何排序、分组、折叠、注释和样式操作只修改 `ViewSpec`。

### FR-002 稳定对象标识

每个数据项和分组必须使用稳定 ID。重复名称、名称修改和重新排序不得破坏来源映射。

### FR-003 统一命令模型

所有编辑入口必须转换为类型化命令。第一阶段命令至少包括：

- `moveItem`
- `moveGroup`
- `createGroup`
- `ungroup`
- `collapseGroup`
- `expandGroup`
- `pinItem`
- `unpinItem`
- `setSort`
- `setAnnotation`
- `undo`
- `redo`

### FR-004 瀑布图

瀑布图必须支持贡献项排序、分组、折叠、展开、起点/终点/小计锁定、正负项展示和合计校验。第一阶段不支持通过拖动柱高修改金额。

### FR-005 分类条形图与柱状图

条形图和柱状图共享分类编辑模型，支持分类排序、分组、折叠、展开、固定关键项和恢复默认顺序。第一阶段仅支持单序列分类图，不包含堆叠、分组系列或双轴组合图。

### FR-006 图表直接操作

图表必须区分柱子点击、柱子拖动和空白区域框选，提供明确的可拖拽目标、实时重排预览、落点指示、拖拽取消、非法落点反馈和提交后的短过渡动画。框选多个同父级连续节点后，用户可以命名并原子地创建折叠分组。

### FR-007 结构大纲

结构大纲必须显示顺序、层级、折叠状态、锁定状态和来源数量，并支持鼠标与键盘操作。

### FR-008 历史与恢复

系统必须支持撤销、重做、命令历史和视图恢复。历史操作不得复制或修改原始数据。

### FR-009 财务不变量校验

系统必须在命令执行前后校验：

- 来源项不丢失、不重复。
- 分组聚合值等于其来源项按指定口径计算的结果。
- 排序前后总体金额一致。
- 锁定项不被非法移动或归组。
- 撤销后恢复完全一致的 `ViewSpec`。

### FR-010 AI 候选命令

AI 只能返回受 schema 约束的候选命令。系统必须展示受影响对象、顺序变化、聚合变化和校验结果；用户确认前不得写入当前 `ViewSpec`。

### FR-011 保存与加载

系统必须支持保存、加载和版本化 `ViewSpec`，并在源数据发生兼容变化时给出可解释的映射或冲突提示。

### FR-012 导出

第一阶段必须支持高质量 SVG 和 PNG 导出。导出结果必须与当前可见图表一致，并保留标题、标签、注释、顺序和折叠状态。

### FR-013 安全图表配置

宿主可以通过 TellPlot 语义配置调整标题、财务语义色、坐标轴、数值标签、Tooltip、数字格式和动画。配置不得覆盖 G2 数据、编码、稳定 ID、场景命中、事件注册或拖拽状态机；屏幕、导出和无障碍摘要必须共享一致的显示语义。

## Non-Functional Requirements

### NFR-001 正确性

核心财务不变量测试必须全部通过。发现来源丢失、重复、合计漂移或非法锁定项变更时，命令必须拒绝提交。

### NFR-002 交互性能

在 200 个可见项目以内，拖拽反馈目标为每帧更新；普通重排提交后的可见反馈目标为 150ms 内开始。性能验收使用真实浏览器和真实 G2 图形，不使用纯 Mock 代替。

### NFR-003 可打断动画

重排和折叠动画必须可被下一次操作打断或快速完成，不得锁住编辑器。系统必须支持 `prefers-reduced-motion`。

### NFR-004 可访问性

核心排序与层级操作必须存在键盘等价路径，焦点清晰，状态变化可以被辅助技术识别。

### NFR-005 隐私

AI 功能默认不得向外部 provider 发送财务数据。任何外部发送必须基于明确配置、范围提示和用户授权。

### NFR-006 可观测性

系统必须记录不含敏感金额的命令类型、失败类型和性能指标，用于定位交互问题；不得把财务明细写入普通日志。

## Functional Scope

### Phase 1A 确定性编辑基础

- 瀑布图。
- 单序列分类条形图。
- 单序列分类柱状图。
- 图表直接排序。
- 结构大纲排序。
- 分组、取消分组、折叠、展开。
- 锁定关键项。
- `ViewSpec`、命令模型、撤销重做和不变量校验。
- SVG、PNG 导出。

Phase 1A 按两个可验收切片推进：

1. 瀑布图端到端切片：先完成真实财务数据导入、排序、分组、折叠、撤销、校验和导出，复现已经验证的公司工作流。
2. 分类图验证切片：在同一命令与 `ViewSpec` 模型上实现条形图和柱状图。二者视为同一分类图能力的横向与纵向布局，不分别建设交互内核。

只有两个切片都通过验收后，才评估哪些能力适合抽取为公共组件或 SDK。

### Phase 1B AI 辅助

- 自然语言转换为受约束候选命令。
- 修改预览、拒绝、确认和撤销。
- 支持排序、阈值归组、折叠和强调等明确意图。
- AI 不参与金额计算和财务正确性裁决。

## Non-Goals

- 通用 BI 平台、Dashboard 设计器或数据准备工具。
- 第一阶段支持折线图、饼图、散点图、地图、桑基图或复杂组合图。
- 第一阶段支持堆叠条形图、多序列分组柱状图和双轴图。
- 通过拖动图形修改原始金额。
- 自动发布、自动写回财务系统或无确认 AI 执行。
- 同时支持多个图表渲染引擎。
- 第一阶段实现可编辑 PowerPoint 图形对象或 PowerPoint Add-in。
- 移动端专项适配。

## Interaction And Animation Strategy

### 图表层

- G2 作为第一阶段唯一图表渲染引擎。
- 图形进入、更新、退出和数据重排优先使用 G2 原生动画。
- 拖拽期间的位置反馈由指针事件和逐帧渲染驱动，不通过长时间补间动画追赶指针。
- 不建设独立 `AnimationEngine`。

### UI 层

- 结构大纲、折叠面板、预览差异和浮层属于 DOM/React UI。
- Motion 是 UI 层布局重排、进入退出和 reduced-motion 支持的首选候选。
- Motion 不接管 G2 Canvas 的图形状态和数据过渡。
- 是否正式引入 Motion 必须由 Phase 1A 原型验证，并记录在后续 TDR。

### Motion Guidelines

- 拖拽跟手，不使用弹簧延迟指针位置。
- 提交后允许短距离位置过渡。
- 财务工具默认低弹性或无弹性，不使用夸张回弹。
- 非关键装饰动画不进入第一阶段。

## Data And Integration Needs

### SourceData

至少包含稳定 ID、名称、金额、类型、可选父级、来源引用和口径信息。

### ViewSpec

至少包含图表类型、显示顺序、分组树、折叠状态、锁定状态、排序规则、注释、视觉强调和版本。

### CommandLog

至少包含命令 ID、命令类型、参数、执行时间、执行来源、前后版本和校验结果。执行来源区分 `direct`、`outline`、`keyboard` 与 `ai`。

## Edge Cases

- 重复名称但来源 ID 不同。
- 金额为零、负数、缺失或非有限数值。
- 只有起点和终点、没有贡献项。
- 任意深度分组嵌套、循环引用、孤儿分组、空分组、单项分组和跨 subtotal segment 分组。
- 外层分组折叠后再展开时，内层分组保持各自原有折叠状态。
- 同一可见柱同时代表折叠内组，并且是已展开父组的首个可见节点。
- 折叠组中包含锁定项。
- 拖拽过程中取消、离开图表或窗口失焦。
- AI 预览期间用户又进行了直接操作。
- 源数据更新后 `ViewSpec` 引用的项目不存在或新增。
- 标签过长、分类过多和图表宽度不足。
- reduced motion、键盘操作和高缩放比例。

## Constraints And Assumptions

- 产品桌面端优先。
- 第一阶段使用 G2，不做多引擎抽象。
- 第一阶段采用 React 组件包与薄参考编辑器，公共行为必须在组件包内完成。
- 已上线的真实瀑布图组件及使用反馈应作为后续 spec 的主要输入。
- 新前端项目确认后默认使用 `pnpm`。

## Success Criteria

- SC-001：至少 3 名真实财务分析用户能从结构化数据完成图表排序、分组、折叠和导出，不需要开发人员介入。
- SC-002：同一输入数据在任何合法编辑序列后均保持来源完整和总额一致，阻断性不变量缺陷为 0。
- SC-003：与当前真实工作流基线相比，完成一张汇报用瀑布图的中位时间降低至少 30%。
- SC-004：用户可以分别通过图表和结构大纲完成核心排序任务，并能成功撤销。
- SC-005：Phase 1B 的受支持 AI 指令全部产生可解释候选命令，未经确认写入次数为 0。

## Acceptance Criteria

- AC-001：用户可以拖动一个未锁定瀑布贡献项到合法位置，金额和最终合计不变。
- AC-002：用户可以将同父级连续项目或分组递归归组并折叠；任意层级折叠值等于全部后代来源项聚合值，展开后树结构、来源顺序与后代折叠状态完整恢复。
- AC-003：用户可以在条形图与结构大纲中得到一致的分类顺序。
- AC-004：锁定的起点、终点或合计项不能被非法移动，界面说明原因。
- AC-005：撤销和重做恢复完全一致的顺序、分组、折叠和注释状态。
- AC-006：导出 SVG 与当前可见图表的顺序、标签、折叠和强调状态一致。
- AC-007：AI 候选命令在用户确认前不改变当前图表。
- AC-008：宿主可以调整批准的图表呈现字段，默认调用保持当前视觉和交互；公共 API 不暴露原始 `G2Spec` 或 chart instance。

## Clarifications

- CL-001：瀑布图拖拽、排序、折叠与展开来自已上线的公司项目和真实 PPT 汇报需求。
- CL-002：产品保留直接操作，同时考虑使用 AI 处理复杂或批量调整。
- CL-003：第一阶段从瀑布图和分类条形/柱状图开始，不追求全图表类型覆盖。
- CL-004：现有实现不作为新架构基础；仓库先回到 SSOT 驱动的产品定义阶段。
- CL-005：动画目标是增强状态连续性和操作反馈，不独立构成产品能力。
- CL-006：Phase 1A 的分组采用无固定深度上限的递归树；图表负责直观的同父级操作，大纲负责精确的跨层级操作。

## Confirmed Decisions

### CD-001 第一阶段交付形态

交付可嵌入的 React 组件包与薄参考编辑器。第一阶段不建设独立 SaaS，不以通用第三方 SDK 为验收目标。

### CD-002 演示文稿导出边界

第一阶段交付 SVG 和 PNG。可编辑 PowerPoint 图形对象与 PowerPoint Add-in 不在第一阶段范围内。

### CD-003 AI 数据边界

Phase 1A 只提供确定性命令接口，不连接外部 AI provider。Phase 1B 在独立审批中确定公司内模型、私有部署或 BYOK 边界。

### CD-004 产品名称

产品品牌使用 `TellPlot`，代码仓库使用 `tellplot`，npm scope 使用 `@tellplot`。公共包、持久化 schema、DOM scope、日志前缀和导出默认文件名使用一致的品牌命名空间。

### CD-005 递归分组与画布直接操作

`ViewSpec` 使用规范化递归分组树。图表通过柱子拖动、空白框选和临时 DOM 操作按钮完成同父级编排；跨层级移入和移出由结构大纲完成。交互预览不写入命令历史，松开或确认时只提交一个确定性命令。

### CD-006 图表配置边界

- 公共配置使用 TellPlot 语义类型，不透传任意 G2 options。
- `chartAppearance` 属于宿主呈现配置，不写入 `ViewSpec`。
- G2 adapter 独占数据、编码、稳定 key、比例尺几何、事件与交互状态。
- 配置扩展以真实财务图表需求为依据，并保持屏幕、导出和无障碍一致。
